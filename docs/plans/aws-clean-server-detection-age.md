Implementation handoff for GPT 6.2 Sol · 22 November 2026 · reviewed on `dev` at `d691761fb`, including local changes. Recheck the working tree before editing, especially the in-progress CrowdStrike import, remediation DTOs and V305 migration.

## Metric to implement

Count every known EC2 server in SecMan inventory once. A server is overdue as soon as one eligible, still-open finding was first detected **on that server** strictly more than 30 elapsed days ago. Freeze one observation instant for the calculation. Exactly 30 days qualifies as within the window. A CVE published 100 days ago and first detected two days ago on A contributes zero overdue findings on A, even if the same CVE has been open for 40 days on B.

Use the stored EC2 asset population with a nonblank instance ID, including servers with no Falcon agent or recent contact. Account placeholders and on-premises systems fall outside it. The unit is the canonical SecMan server after existing identity reconciliation. Audit duplicate account/instance records before rollout. Avoid counting one machine twice through a findings join or merging unrelated machines by hostname.

Proposed interpretation of “without old vulnerabilities” is verified clean as of the last trustworthy findings observation. Keep the existing unknown-coverage safeguard, and expose it on the card. Apply the following rules in order to each inventory server.

| Class | Rule |
|---|---|
| Overdue | At least one applicable open finding with reliable host detection strictly before the cutoff. Positive evidence suffices even when other severities are unassessed. |
| Unknown | No established overdue finding, and coverage for the claimed scope is missing, incomplete or belongs to a superseded identity, or an applicable finding has an unknown/unreliable detection date. |
| Clean | Sufficient valid coverage and every applicable open finding is within the window. A verified empty result qualifies. |

Compute `100 × clean / total`, rounded once to one decimal. Require `total = clean + overdue + unknown`. Keep unknowns in the denominator. For an empty fleet show “No known AWS servers”. For a wholly unknown fleet show “Coverage unknown” with the count. For a measured fleet with zero verified clean servers, display 0% alongside the counts. A failed or pending first calculation is “Not available”.

**Scope assumptions for implementation.** The unqualified card covers all severities of supported findings. A limited High/Critical import may establish an overdue server but cannot certify the absence of old findings in other severities. Preserve the documented SecMan convention of excluding active approved exceptions and installer artifacts from actionable findings and describe those exclusions in the card detail. Pending or expired exceptions do not qualify. The fixed 30 days is independent of the configurable notification SLA. If the product owner wants a High/Critical-only metric, that is a different label and coverage contract; do not silently substitute it to obtain a higher percentage.
