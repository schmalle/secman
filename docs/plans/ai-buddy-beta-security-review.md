# AI buddy(beta): implementation security review

Scope: the AI buddy working-tree implementation, BETA enum/UI changes, recorded-system route, configuration, evidence URL-policy extraction and feature tests. Existing unrelated branch changes relative to origin/main are not part of this patch. Review covers controller/service authorization, SQL/snapshot transactions, job ownership/lifecycle, evidence parsers/graph/report validation, outbound transport/model payload/provider routing, UI rendering and operational controls. This is a semantic source review plus repository static/test gates; it is not a paid-provider penetration test.

| OWASP 2021 | Result and reused control |
|---|---|
| A01 Broken access control | Authenticated controller deliberately accepts stale role claims, then `BetaFeatureAccess` reloads enabled user/identity/roles. `AiBuddyAccessGuard` rebuilds current Authentication and invokes `AssetFilterService.canAccessAsset`; report/status/cancel are owner+asset scoped. Stale ADMIN claims cannot take the global shortcut. Role/asset revocation blocks publication and retrieval. BETA does not enter legacy admin permissions. |
| A02 Cryptographic failures | Existing HttpOnly auth cookie and pass-cli secret config retained. SHA-256 is used only for content/candidate fingerprints, never credential verification. Model projection excludes identity, credentials, raw text and database finding IDs. |
| A03 Injection | SQL values are bound; only the constant shared exception predicate is interpolated. Provider FQL AIDs are hex-validated and URL-encoded. No shell/commands/actions are executed. No HTML/Markdown sink; React escapes plain text. Model returns a closed ID permutation. |
| A04 Insecure design | Jobs, request frequency, retained bytes, snapshots, candidate graph size/depth, model context/output/cost, evidence requests/bodies and deadlines are bounded. Repeatable-read snapshot completes before HTTP. Exhaustive ledger distinguishes unknown and conditional coverage. Cancellation/client lease and duplicate admission are server-controlled. |
| A05 Security misconfiguration | Disabled by default; explicit model/providers/key/single-instance acknowledgment. No debug/mock provider path in production. Existing CSP/CORS/security headers unchanged. Safe error codes and no-store responses. |
| A06 Components | No dependencies or manifest versions changed. Existing JDK HTTP, Jackson, Caffeine, Micronaut, React and repository test infrastructure used. |
| A07 Authentication | Existing authentication provider/session mechanism retained. CurrentIdentityRule defers only role-claim equality under /api/ai-buddy/ to the mandatory live guard; identity, enabled-user, principal name and email checks remain, and other paths still reject stale roles. Enabled-user and principal-ID/name consistency rechecked; UI role payload is not an authority. No longer-lived sessions or weakened cookies. |
| A08 Integrity | Bounded duplicate-key/trailing-token/depth JSON parsing; vendor product/CVE/remedy edges and same-variant supersedence validated outside the model. Closed output membership/dependency checks and final report/count/reference/state validation. Untrusted provider advice remains explicitly unverified. |
| A09 Logging | Actor+asset denials and job admission/outcome logged; provider partial-error codes/usage/reservation recorded. No raw provider response, prompt, asset text, API key or exception body is logged by these components. |
| A10 SSRF | Shared HTTPS/exact-host/public-address policy reused for EOL/evidence transport. Redirects disabled; no model/user source URL is fetched. Evidence links restrict Microsoft source paths/query patterns and omit credentials/fragments/foreign destinations. |

No unresolved HIGH/CRITICAL application finding was identified in this review. Final-tree verification passed: 1,739 backend, 164 CLI and 75 shared tests; 318 frontend tests/build/lint (zero lint errors); both AI buddy browser cases; 74-page dual-role JavaScript scans; two consecutive full vulnerability-exception lifecycle runs. All database fixtures used the isolated runner; no paid provider test was run. Static REVIEW decisions: authenticated controller scope is deliberate because current database roles are the authority; SHA-256 fingerprints are non-secret content; URL creation flows through the fixed-host transport policy; EOL compatibility is covered by its existing tests. Scanner findings in pre-existing AssetController/CrowdStrike import changes are outside this patch and are not claimed as newly reviewed or fixed.

Deployment conditions remain explicit: network egress must deny private destinations (DNS validation and connection resolution are separate); an organizational owner must approve OpenRouter/provider handling and verify a compliant ZDR route; use a provider-side spending ceiling because process-local budget counters reset after restart and cancelled calls may be billed. No model/provider route fallback relaxes these requirements. The feature remains off until configured; actual provider structured-output/routing behavior requires a deliberate small non-identifying rollout canary.


## Shared admin configuration review — 2026-10-10

AI buddy now resolves the active persisted `TranslationConfig` on every availability check and captures its values for provider requests. It has no separate environment credential/model/enablement fallback. Existing ADMIN-only mutations and masked authenticated reads are retained. Request validation rejects enabled records without a concrete model, standard OpenRouter HTTPS base URL, approved routes, single-instance acknowledgment and finite positive budget/price values. Validation uses a copy before updating a persisted entity, so a rejected update cannot silently dirty the original record.

- **A01 / A07:** existing ADMIN mutation checks remain; a USER+BETA direct configuration update is tested as forbidden. The live beta/asset/owner checks remain required independently of configuration availability.
- **A02:** the shared key uses the existing `EncryptedStringConverter`, with a widened column. A disposable-database test verifies ciphertext storage, plaintext legacy readability and masked API output. Existing deployment encryption secrets must remain stable and configured; legacy plaintext is encrypted on its next save. There is no new key in the browser, environment examples, fingerprints or logs.
- **A03 / A08:** settings are typed and bounded; model instructions and closed candidate-ID validation are unchanged. An enabled configuration cannot choose an arbitrary outbound URL. Both evidence sources use the captured job settings rather than stale startup flags.
- **A04 / A05:** disabling/removing the active record fails closed, configuration changes abort running work at checkpoints, and completed reports indicate changed settings. Daily reservations are retained across configuration changes. Feature defaults remain disabled, and privacy/routing constraints cannot be weakened in the form.
- **A06:** no new dependency is introduced.
- **A09:** successful configuration saves log actor/config ID, outcome and enablement only. Database/configuration failures return generic messages; no credential or raw exception payload is logged by the new settings resolver.
- **A10:** AI provider requests require the fixed standard OpenRouter base; existing evidence host/path/public-address controls remain. Existing translation consumers keep their current configuration behavior; this change does not expand their outbound access.

Migration V285 adds nine disabled-by-default settings and widens the existing credential column. No normal database was modified during implementation. Rollback requires retaining decryption support for credentials saved by the new binary, and removing BETA assignments before deploying an enum that cannot read them. No unresolved HIGH/CRITICAL finding was identified in the shared-configuration diff. Updated execution evidence is recorded in `docs/AI_BUDDY.md` after the regression gates complete.


## Shared configuration save correction — 2026-10-10

The earlier readiness-on-save rule prevented saving shared LLM settings when AI buddy was enabled but its provider list or single-instance acknowledgment was incomplete. Persisted shared configuration validity is now separate from AI buddy readiness. Common fields and finite positive bounded prices/budgets remain validated. `AiBuddySettings.unavailableReason()` is unchanged and remains enforced by capabilities, job admission, lookup/checkpoints and provider requests, so saved incomplete/unsupported settings cannot cause outbound model calls. Existing ADMIN-only writes, masked reads, key preservation and encryption are unchanged. A01/A02/A04/A05/A10 controls remain intact; no unresolved HIGH/CRITICAL issue was identified in this correction. A03/A06/A07/A08/A09 have no new sinks, dependencies, session behavior or log changes. The browser regression saves enabled beta settings with blank providers and no acknowledgment, then confirms persistence and unavailable capabilities. Concrete current Sol/Sonnet presets add no dynamic URL fetching and do not change an existing stored model.
